# Goal Loop — D405 AVFoundation Format Inventory v1

## Mission

Measure the exact D405 native AVFoundation format surface without opening a
capture session, then let an independent evaluator determine whether a frozen
424×240 near-5-fps candidate exists for a future two-input native common
session. Do not retry the sealed nested-lifecycle family.

## Ordered Source of Truth

1. The owner's evaluator-owned Twin-fidelity closure objective.
2. Clean exact baseline
   `3fafda3b7429f6c727afaacade86346791e72b52`.
3. The sealed nested-lifecycle terminal-negative receipt and exhausted guard.
4. `configs/evaluations/avfoundation_d405_format_inventory_v1.json`.
5. Exact committed observer/evaluator/runtime identities.
6. `GOAL.md`, project state, orchestration ledger, and run logs.

## Intended Outcome

Exactly one read-only D405 format inventory is content-addressed and evaluated,
or a sealed prerequisite abstention identifies why no trustworthy inventory
could be obtained. A selected candidate is design input only; it does not
authorize or prove a native common session, frame delivery, synchronization,
motion reliability, metric depth, simulator calibration, or task success.

## Acceptance Criteria

1. Preserve S2, both HIL states, C922 v1-v4, D405 reliability, and nested
   lifecycle evidence byte-identically.
2. Commit this prompt and contract before implementing the evaluator or
   observing the device.
3. Reuse only the already-reviewed primitive `Codable` inventory observer; do
   not mutate any execution-bound source.
4. The observer receives the exact D405 name and emits identity, formats, and
   frame-rate ranges only. It creates no capture session and records no sample.
5. The evaluator independently verifies exact name, unique ID, model ID,
   zero-session/sample accounting, schema, finite numeric values, budget, and
   content hashes.
6. Candidate selection is frozen at exact 424×240, target 5 fps, maximum
   0.01-fps deviation, and the declared subtype/tie-break order.
7. Add adversarial tests for camera substitution, malformed/native nonfinite
   values, session/sample mutation, threshold or budget mutation, missing raw
   output, replayed output roots, and non-byte-identical materialization.
8. Commit exact evaluator/test bytes before the sole observation. Execute no
   more than one inventory observation and never change the rule afterward.
9. Seal raw/evaluation/receipt hashes and exact counts. If prerequisites fail,
   abstain rather than fabricate a candidate.
10. Update goal/state/ledger/run log, obtain independent read-only review, and
    keep push authority closed.

## Evidence Standard

Report exact commits/trees; contract, goal, observer, evaluator, compiler,
binary, prelaunch, attempt, raw, evaluation, and receipt hashes; return code;
device/format/range/eligible-candidate counts; selected candidate or
abstention; budget use; tests; frozen-evidence proof; and all closed authority.

  `AVCaptureSession`.

### Assumptions

- The exact D405 remains attached and camera authorization remains granted.
- Its AVFoundation format surface may contain a 424×240 rate range including
  5 fps; the evaluator, not this assumption, decides.

### Recommended Default

- Whether one format supports 424×240 within 0.01 fps of 5.
- Whether AVFoundation can subsequently admit both exact inputs and outputs in
  one session; this inventory does not answer that.
